# 设计说明

## 要解决的问题

一台会移动的机器（笔电）跑着 AstrBot，需要在自己换到某个已知地点时，主动告诉白名单里的会话「我到哪里了」。
约束有三条：

1. 不能花钱调用大模型（这条消息的生成不需要智能）；
2. 不能影响已有的前缀缓存（所以不能往 system prompt 里塞东西）；
3. 不能轮询（笔电常年开着，定时采样网络是无谓开销）。

## 判定信号从哪来

同一地点可以对应多条网络，所以"地点"和"网络"是一对多：

| 信号 | 稳定性 | 能不能定位 |
|---|---|---|
| SSID | 用户可改，路由器重置会变 | 能区分"哪张网"，但不能区分同网的不同房间 |
| 子网前缀 | DHCP 分配，相对稳定 | 能区分不同网段；校园网常见一张 /16 覆盖整栋楼，到此为止 |
| BSSID（接入点 MAC） | 换 AP / 漫游会变 | 校园网下区分教室的唯一信号 |
| 网关 MAC | 路由器换口/换设备会变 | 小网（宿舍）很稳，可作二次校验 |
| 当前 IP | DHCP 会换 | **不能**用于判定，只能展示 |

所以判定是分层的：

```
先看 SSID 与网段 → 能不能认出"是哪张网"
  认不出 → 校园网未标定 / 热点 / 未知
  认得出 → 是否需要更细的区分（同一 campus SSID 下的多个教室用 BSSID）
```

匹配时"给出的条件必须同时成立"（AND），多条命中取最具体的一条，权重：

```
bssid(4) > gatewayMac(3) > subnet(2) > ssid(1)
```

## 触发为什么不用轮询

Windows 提供了事件级的网络变化通知：

- `iphlpapi.NotifyAddrChange`：本机 IP 变化时唤醒（换 Wi-Fi、DHCP 换段、热点接入、有线插拔）；
- NapCat 的 `meta_event.lifecycle.connect`：QQ 侧重连时触发（`bot.subscribe` 可挂多个监听，不会顶掉 AstrBot 自己的）；
- 插件启动后判一次：覆盖"开机时就已经在目标网络"的情况；
- 手动命令：兜底。

注意一个容易踩的坑：NapCat 与 AstrBot 之间是 **127.0.0.1** 的本地 WebSocket，换 Wi-Fi 时那条连接不会断，
因此 `lifecycle.connect` 只在 NapCat/AstrBot 重启时出现，**不能当作换网信号**。主信号必须是 IP 变化。

## 为什么需要 settle_seconds

刚连上（或刚 DHCP 完成）时，BSSID 和 IP 可能还没稳定，立刻读会误判。
所以事件到达后延迟 `settle_seconds`（默认 12 秒）再读一次指纹，且同一时间只允许一个判定在跑。

## 幂等

`state.json` 记录「上次指纹 + 时间」。指纹 = `ssid|subnet|bssid`。
同一指纹在 `cooldown_hours` 内不重复上报：避免 QQ 抖动、Wi-Fi 重连把同一条消息刷屏。
换地点或换网段会立刻上报。手动 `/报点` 不受冷却限制。

## 标定（/标定）

不硬编码任何网络拓扑，地点由人在现场录：

- 非校园网：`ssid + subnet`（不记 BSSID，路由器重启换 BSSID 不影响）；
- 校园网：`ssid + subnet + bssid`（同网段多教室只能靠 AP 区分）。

录完立即写 `locations.json`，并回显它记下的条件，方便核对。

## 已知边界

- **同网段漫游不触发**：从 A 教室走到 B 教室，Wi-Fi 不断、IP 不变，就没有事件。这是设计取舍——那种情况用 `/报点` 手动补最省事。
- **热点只按 SSID 认**：手机的 MAC 会随机化（本地管理地址且每次不同），网段也会随运营商变，所以热点默认落到"不能确定"。
- **BSSID 不是永久的**：AP 负载均衡、换设备都会变，教室标定需要重做。
- **隐私**：地点表里是真实 SSID/BSSID/网段，属于可定位信息，不要提交到公开仓库。
